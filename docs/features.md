# Current Beta Features

Waquela Beta combines implemented product workflows with client-dependent AI connections. The descriptions below cover the current bounded capabilities, not a guarantee that every workflow works through every client.

## Cards and Current Reads

- Create Markdown-backed Cards.
- Discover your Cards and read their current accepted information.
- Organize information in sections and structured Node facts.
- Use an English-first web interface.

Current is a view derived from accepted information. Reading a Card or receiving an AI suggestion does not itself change that information.

## Saved Proposals and Supported Apply

Save proposed changes for review. Explicit Human authorization is required before applying selected supported changes.

Current supported changes cover:

- A Card title.
- Accepted facts on an identified Node.
- The complete body of a Markdown section.

Updates are revision-aware: the relevant accepted version must match the proposal's expected version. Not every saved Proposal is executable. Arbitrary lifecycle changes and general autonomous actions are not offered as current Apply features.

## Private and Public Cards

Private Card reads require appropriate access. Scoped sharing is available for supported workflows; broader multi-user acceptance is still experimental.

Owners can publish selected snapshots and withdraw their availability. Available public publications can be browsed without signing in. A publication is a snapshot, not anonymous access to the owner's private workspace.

Withdrawal stops availability through Waquela. It does not erase historical records or external copies.

## Personal Transaction Offices and External Submissions

A personal public Office accepts external information for its owner. Submissions appear in the owner's private Inbox for review.

Visitor identity and reply methods are self-declared and unverified. An external submission does not automatically modify a Card, create a Proposal, grant access, or establish a trusted relationship.

## Collaboration: Buying a Used Car

Waquela's collaboration foundation includes implemented and tested Cards, Publication, Public Discovery, Transaction Offices, Submissions, Inbox, supported Proposal / Apply, and two-person, multi-AI transaction interactions. These are existing capabilities, not solely roadmap concepts. Testing individual paths does not establish acceptance of every client combination or a complete multi-party transaction.

The fictional Buying a Used Car example uses a buyer with ChatGPT, a seller with Claude, an inspector, and a family member using their own AI-assisted workflow. The buyer publishes selected requirements; other participants contribute an offer, a report, and advice through available submission paths. The buyer reviews the information, compares proposals, and decides which supported changes to authorize.

Each participant keeps control of their own information and decisions. External offers, reports, and advice do not automatically become Card facts or saved Proposals. A supported Proposal and explicit Human-authorized Apply are required to update Current.

| Scope | Status |
| --- | --- |
| Individual Card, publication, discovery, Office, submission, Inbox and supported Proposal / Apply paths | Implemented and tested within their existing evidence boundaries. |
| Two-person, multi-AI transaction interactions | Existing implementation and testing foundation; no universal client or workflow acceptance claim. |
| Continuous collaboration among three or more people | Not accepted end to end. |
| Complete used-car transaction workflow | Not yet end-to-end tested. |
| Automated transaction matching, verified vehicle inspections, identity verification, payments, escrow and guarantees | Not claimed as capabilities of this scenario. |

This scenario combines existing Waquela Beta capabilities with an illustrative multi-party workflow. Individual interaction paths have been implemented and tested, while the complete used-car transaction scenario has not yet undergone end-to-end acceptance.

Buying a Used Car is the planned narrative for the future walkthrough video. It does not promise automatic completion of a purchase or new transaction services.

## AI Connections

| Client | Evidence boundary |
| --- | --- |
| ChatGPT | Supported and Human-tested for representative Card workflows. |
| Claude | Supported; full workflow acceptance remains incomplete. |
| Grok | Limited / experimental. |
| Codex | Limited / experimental. |

AI tool availability and behavior vary by client, account, plan, platform, and version. Installation guidance on the official website remains the current source for connection settings.

A reported explicit Mixed Inbox V2 request returned a legacy projection through an AI connection. The production cause remains unresolved. ChatGPT Mixed Inbox V2 production acceptance is incomplete; the private Inbox capability should not be read as a claim of complete AI-client Inbox parity.

## Boundaries

Waquela Beta does not promise a general verified identity network, independent Agent execution, freely editable arbitrary topologies, or a completed general-purpose collaboration platform. Broader collaboration and Agent-assisted ideas are exploration topics.
